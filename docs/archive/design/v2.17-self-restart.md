# Franky process restarts itself — design decision (archived)

**Status:** implemented

**Affects:** `src/coding/restart.zig`, `src/coding/mod.zig`, `src/coding/modes/proxy.zig`, `src/coding/session.zig`

## What was implemented

- **`src/coding/restart.zig`** — new module: `init`, `deinit`, `spawnAndExit`. Caches exe path + argv at bootstrap; spawns fresh process via `std.process.spawn` then `std.process.exit(0)`.
- **`src/coding/mod.zig`** — exports `pub const restart`.
- **`Session`** — added `restart_requested: std.atomic.Value(bool)`.
- **`proxy.run()`** — accepts `original_argv`; passes to `initSession`.
- **`initSession()`** — calls `restart_mod.init(original_argv, ...)` to cache argv (best-effort, warns on failure).
- **Accept loop** — polls `restart_requested` each iteration; breaks when set.
- **Restart sequence** — closes listen socket (`server.deinit`), broadcasts `event: close` to SSE subscribers, calls `restart_mod.spawnAndExit`. If spawn fails (OOM), logs error and returns.
- **`/restart` slash command** — sets `side_effect = .restarting`, `restart_requested = true`.
- **`POST /restart` HTTP route** — sets flag, responds `{"ok":true,"restarting":true}`.
- **Unit test** for init/deinit caching; slash command test; HTTP route test; help text coverage.

## Approach B — spawn-and-exit ★ chosen & implemented

Parent spawns child with `std.process.spawn`, gives short head start, exits normally. Child starts `main()` fresh.

```
trigger → server.deinit(io)    // close listen socket FIRST → port freed
        → spawn(new_binary, argv, env)
        → sleep(200ms)          // brief head start for child
        → exit(0)               // normal exit, defer chains run
```

**Port-conflict mitigation:** Parent calls `server.deinit(io)` *before* spawning. `reuse_address = true` on listen socket. Gap <1ms.

**Pros:** Simplest; `std.process.spawn` already in codebase; no signal handlers; parent exits normally → defer chains fire; works on macOS; complexity 1.5/5.

**Cons:** Two processes briefly coexist; ~200ms port-free window (browser EventSource retries automatically).

## Platform compatibility

Both `execve` (Approach A) and `std.process.spawn` (Approach B) are POSIX, available on macOS. Proxy links libc (`link_libc = true` in `build.zig`).

## Trigger surface

- **Implemented:** `/restart` slash command + `POST /restart` HTTP route.
- `finish_task` extension (restart bool field) → deferred to v2.
- SIGHUP signal handling → deferred to v2.

## v1 scope

**Proxy mode only.** Print mode is single-shot; interactive gets it in v2.

## End-to-end flow

1. User/agent triggers restart
2. Handler sets `session.restart_requested = true`
3. Server closes listen socket: `server.deinit(io)` → port freed
4. Server spawns child with argv preserved from bootstrap
5. Server sleeps 200ms
6. Child's `main()` runs, binds port (`reuse_address = true`)
7. Parent exits cleanly → session persists, replay ring lost but transcript on disk
8. Browser EventSource reconnects with Last-Event-ID → `replay_gap` → falls back to `GET /transcript` → full rehydration

## Argv preservation

Original `argv` available in `print_mode.run()` at proxy call site. Stored on `Session` as duplicated `[]const []const u8`. `restart_mod.init()` deep-copies argv; `spawnAndExit()` passes to `std.process.spawn`.
