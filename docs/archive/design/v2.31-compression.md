> **Goal:** Integrate the zompress content-aware compression library into the franky

> tool-heavy sessions with zero data loss (CCR-based retrieval).

## 1. Architecture Overview

### Current State (franky)

```
Tool output  ──►  makeToolResult()  ──►  8 KiB flat truncation  ──►  LLM
                        │
                        ▼
               offloadToolResults()  ──►  disk file  ──►  placeholder text
               (v3.0, opt-in, keeps N recent)
```

The current truncation is **content-blind** — it cuts at byte boundaries regardless
of whether it's JSON, logs, diffs, or code. Error messages in the middle of a build
log are just as likely to get dropped as INFO lines.

### Target State

```
Tool output  ──►  makeToolResult()
                        │
                        ├──► zompress.detect() ──► zompress.compress()
                        │         │                       │
                        │         ▼                       ▼
                        │   ContentType            Compressed output
                        │   (json_array,            (structured, lossy)
                        │    build_output,                │
                        │    git_diff,                    ▼
                        │    search_results,       [CCR Store ◄── original]
                        │    source_code,                │
                        │    plain_text)           CCR marker in output
                        │                              │
                        ▼                              ▼
               If compression saved tokens:      use compressed
               Else: fall back to 8 KiB cap

                ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─

Conversation  ──►  maybeCompact()  ──►  zompress.compressConversation()
                        │                              │
                        ▼                              ▼
               compaction_summary role          Compacted history
               (already in defaultConvertToLlm)  (first N messages)
```

## 3. Phase 1: Content-Aware Tool-Result Compression

### 3.1 Modify `makeToolResultMessage()` in `src/agent/loop.zig`

> ✓ decided: **`min_tokens_to_compress = 100` is the global default, but it
> must remain overrideable per content type via `CompressConfig`.** Specifically:
> `plain_text` and `source_code` may need a higher gate (e.g. 200 / 500) because
> their compression is lossier; `json_array`, `build_output`, `search_results`,
> `git_diff` keep 100. The byte-length safety check below the zompress call
> (`result.compressed.len < t.text.len`) is the real guardrail — the token gate
> is a fast-path skip for inputs we'd never benefit from, not a correctness
> boundary.

**Current** (line ~1328-1343):
```zig
.text => |t| blk: {
    if (t.text.len <= truncate.tool_result_max_bytes) break :blk try cb.dupe(allocator);
    var end = truncate.tool_result_max_bytes;
    while (end > 0 and (t.text[end] & 0xc0) == 0x80) end -= 1;
    const size_str = try truncate.formatSize(allocator, t.text.len);
    defer allocator.free(size_str);
    const text = try std.fmt.allocPrint(allocator, "{s}\n[...{s} truncated]", .{ t.text[0..end], size_str });
    break :blk .{ .text = .{ .text = text } };
},
```

**Target:**
```zig
.text => |t| blk: {
    // Phase 1: Attempt content-aware compression first
    if (t.text.len >= 256) {  // Skip tiny outputs
        const result = zompress.compress(allocator, t.text, .{
            .smart_crusher_enabled = true,
            .log_compressor_enabled = true,
            .search_compressor_enabled = true,
            .diff_compressor_enabled = true,
            .min_tokens_to_compress = 100,
        });
        // Only use compressed version if it actually saved space
        // (gate enforced both at zompress's `min_tokens_to_compress` and again
        // here on byte length, to also cover cases where the model tokenizer
        // differs from zompress's heuristic by more than 10%).
        if (result.tokens_saved > 0 and result.compressed.len < t.text.len) {
            // If the tool text contains known patterns that compress well,
            // the compressed version is more informative than flat truncation
            break :blk .{ .text = .{ .text = result.compressed } };
        }
        // Compression didn't help (or text was plain/uncompressible)
        // Fall through to the existing 8 KiB cap
        allocator.free(result.compressed);
        allocator.free(result.transforms_applied);
        allocator.free(result.ccr_keys);
    }

    // Existing 8 KiB fallback truncation
    if (t.text.len <= truncate.tool_result_max_bytes) break :blk try cb.dupe(allocator);
    var end = truncate.tool_result_max_bytes;
    while (end > 0 and (t.text[end] & 0xc0) == 0x80) end -= 1;
    const size_str = try truncate.formatSize(allocator, t.text.len);
    defer allocator.free(size_str);
    const text = try std.fmt.allocPrint(allocator, "{s}\n[...{s} truncated]", .{ t.text[0..end], size_str });
    break :blk .{ .text = .{ .text = text } };
},
```

**Why this works at tool-granularity:**
- JSON arrays (k8s pod lists, directory listings) → SmartCrusher keeps first+last+errors, drops ~80%
- Build logs (pytest, cargo, npm) → LogCompressor keeps only error lines, drops ~90%
- Git diffs → DiffCompressor keeps change-dense hunks, drops ~70%
- Grep results → SearchCompressor keeps first/last per file, drops ~80%
- Zig source code → CodeCompressor keeps signatures + key statements, drops ~70%
- Plain text → compression detects no structure, passthrough -> falls to 8 KiB cap (no regression)

## 4. Phase 2: Conversation Compaction

### 4.1 The Compaction Trigger

Add a configurable threshold in `src/agent/types.zig`:

```zig
// In Agent.Config:
/// v4.0 — conversation compaction. When the transcript exceeds this many
/// messages, older messages are compressed into a single "compaction_summary"
/// message. 0 disables compaction (default).
compact_after_messages: u32 = 0,

/// v4.0 — number of most recent messages to protect from compaction.
/// These stay in full fidelity so the model has immediate context.
/// ✓ decided: keep the flat default of 8 messages; do **not** tie it to
/// `compact_after_messages` via a percentage. The empirical sweet spot
/// reported in the compaction literature is "last system-prompt worth of
/// turns" (≈ the 8–10 most recent exchanges), and a percentage-based
/// default is harder to reason about for a user who sets
/// `compact_after_messages = 200`. Users who want a larger buffer can
/// raise it explicitly.
compact_protect_recent: u32 = 8,

/// v4.0 — path to an optional on-disk CCR store for retrieving
/// compacted originals. Null disables CCR (compacted content is
/// permanently dropped).
ccr_store_path: ?[]const u8 = null,

```

### 4.2 The Compaction Function

New file: `src/agent/compaction.zig`

```zig
const std = @import("std");
const zompress = @import("zompress");
const at = @import("types.zig");

/// Compact the conversation history. Replaces messages[0..n-protect_recent]
/// with a single compaction_summary message.
pub fn compactConversation(
    allocator: std.mem.Allocator,
    messages: []const at.AgentMessage,
    protect_recent: u32,
    ccr_store: ?*zompress.ccr.CcrStore,
) ![]at.AgentMessage {
    const n = messages.len;
    const protect = @min(@as(usize, protect_recent), n);
    const compact_end = n - protect;

    if (compact_end < 3) return allocator.dupe(at.AgentMessage, messages);  // Too small

    // 1. Concatenate all compactable messages into one blob
    var blob = std.ArrayList(u8).init(allocator);
    defer blob.deinit();
    for (messages[0..compact_end]) |msg| {
        try blob.appendSlice("=== ");
        try blob.appendSlice(@tagName(msg.role));
        try blob.appendSlice(" ===\n");
        for (msg.content) |cb| {
            switch (cb) {
                .text => |t| try blob.appendSlice(t.text),
                else => {},
            }
        }
        try blob.appendSlice("\n\n");
    }

    // 2. Compress the blob
    const result = try zompress.compress(allocator, blob.items, .{
        .min_tokens_to_compress = 100,
    });
    defer {
        allocator.free(result.compressed);
        allocator.free(result.transforms_applied);
        allocator.free(result.ccr_keys);
    }

    // 3. Optionally store the original in CCR
    var ccr_key: ?[]const u8 = null;
    if (ccr_store) |store| {
        ccr_key = store.store(blob.items) catch null;
    }

    // 4. Build the compaction_summary message
    var summary_text = std.ArrayList(u8).init(allocator);
    defer summary_text.deinit();

    try summary_text.appendSlice("The earlier part of this conversation has been compacted.\n\n");
    try summary_text.appendSlice(result.compressed);
    try summary_text.appendSlice(try std.fmt.allocPrint(allocator,
        "\n\n({d} original messages compacted into this summary. {d} token reduction.)",
        .{ compact_end, result.tokens_saved },
    ));
    if (ccr_key) |key| {
        try summary_text.appendSlice(try std.fmt.allocPrint(allocator,
            "\n[CCR key: {s} — use ccr_retrieve to get the full content]",
            .{key},
        ));
    }

    // 5. Build result: [compaction_summary, ...protected_messages]
    var out = std.ArrayList(at.AgentMessage).init(allocator);
    try out.append(.{
        .role = .custom,
        .custom_role = "compaction_summary",
        .content = &.{.text = .{.text = try summary_text.toOwnedSlice(allocator)}},
    });
    for (messages[compact_end..]) |msg| {
        try out.append(try dupeMessage(allocator, msg));
    }
    return out.toOwnedSlice(allocator);
}
```

### 4.3 Wire Compaction into the Agent Loop

> ✓ decided: **Compaction runs at agent start *and* every N turns (both, not
> either/or).** The at-start pass handles sessions resumed from a long
> transcript on disk; the periodic pass prevents the in-session transcript
> from drifting back over the threshold mid-run. We do *not* compact after
> every turn — the `turn_count % 10` cadence is the floor, and the
> transcript-size check (≥ `compact_after_messages`) is the trigger, so a
> short session that never crosses the threshold pays no compaction cost.

In `src/agent/loop.zig`, at the top of `agentLoop()` before the turn loop starts,
and optionally after every N turns:

```zig
// In agentLoop(), after loading the transcript:
if (config.compact_after_messages > 0) {
    const messages = transcript.messages();
    if (messages.len >= config.compact_after_messages) {
        const compacted = compactConversation(
            allocator,
            messages,
            config.compact_protect_recent,
            config.ccr_store,
        ) catch |err| {
            ai.log.log(.warn, "loop", "compact_failed", "err={s}", .{@errorName(err)});
            // Non-fatal — continue with full history
        };
        if (compacted) |c| {
            transcript.replaceMessages(c);
        }
    }
}
```

Or, for periodic compaction (every N turns), add a check in the turn loop:

```zig
// At the end of each turn, after runTurn():
if (config.compact_after_messages > 0 and turn_count > 0 and turn_count % 10 == 0) {
    // Check transcript size and compact if needed
}
```

## 5. Phase 3: CCR-Backed Retrieval Hooks

### 5.1 CCR Store Lifecycle

> ✓ decided: **Hard cap at 10 000 entries (≈ a few hundred MB depending on
> average blob size), oldest-evicted by insertion order (FIFO, not LRU).**
> The store is keyed by content hash, so "least recently used" is hard to
> define cheaply without an access-time field on every entry; FIFO keeps
> the hot path allocation-free. The cap is configurable via a new
> `ccr_max_entries: u32 = 10_000` field on `Agent.Config` so heavy users
> (e.g. `franky-do` running overnight) can raise it. Eviction is a warning,
> not an error — log a `ccr_evicted` event at `debug` level so a user who
> later tries to retrieve an evicted key gets a diagnostic trail, not a
> silent miss.

The CCR store lives as long as the session. It writes to disk periodically.

```zig
// In src/agent/ccr_integration.zig:

const std = @import("std");
const zompress = @import("zompress");

pub const CcrSession = struct {
    store: zompress.ccr.CcrStore,
    allocator: std.mem.Allocator,
    persist_path: ?[]const u8,

    pub fn init(allocator: std.mem.Allocator, persist_path: ?[]const u8) CcrSession {
        return .{
            .store = zompress.ccr.CcrStore.init(allocator),
            .allocator = allocator,
            .persist_path = persist_path,
        };
    }

    pub fn deinit(self: *CcrSession) void {
        if (self.persist_path) |path| {
            // Persist the map to disk before deinit
            self.persist(path) catch {};
        }
        self.store.deinit();
    }

    pub fn store(self: *CcrSession, original: []const u8) ![]const u8 {
        return self.store.store(original);
    }

    pub fn retrieve(self: *CcrSession, key: []const u8) ?[]const u8 {
        return self.store.retrieve(key);
    }

    fn persist(self: *CcrSession, path: []const u8) !void {
        _ = path;
        // ✓ decided: persist on `deinit()` only, as **JSON Lines** (one
        // entry per line: `{"key": "...", "content_b64": "..."}`). No
        // incremental fsync, no SQLite. Rationale: the store is best-effort
        // cache, not a database — losing the last few entries on a hard
        // crash is acceptable; pulling in SQLite for a single-table
        // append-only cache is overkill. If we later need crash safety we
        // can add a write-ahead log without changing the on-disk format.
    }
};
```

## 6. Phase 4: Configuration & CLI Flags

### 6.0 Master Compression Switch

> ✓ decided (v4.0): a single top-level `compression.enabled` field is the
> **master switch** for the entire compression subsystem. When `false` (the
> v4.0 default), none of the per-feature flags take effect — tool-result
> compression, conversation compaction, and CCR are all skipped, regardless
> of what the user has set on the individual knobs. When `true`, the
> per-feature flags (`compress_tool_results`, `compact_after_messages`,
> `ccr_store_path`) are consulted with their existing defaults.
>
> **Precedence rule:** the master switch is evaluated *first*. Reading
> order is: CLI flag → `settings.json` → `Agent.Config` field default.
> The CLI flag always wins, then `settings.json`, then the Zig default.
>
> **Rationale:** a kill switch is the only sane model for a feature that
> touches every tool result and the entire conversation history. Users
> who hit a regression need *one* place to turn it off, not three. This
> also lets us flip the per-feature defaults to "on" in a future v5.0
> without removing anyone's ability to opt out.

#### `settings.json` shape

```json
{
  "compression": {
    "enabled": false,
    "min_tokens_to_compress": 100
  }
}
```

`min_tokens_to_compress` is exposed here too so users can tune the
fast-path gate from `settings.json` without rebuilding.

#### `Agent.Config` field

```zig
/// v4.0 — master switch for the entire compression subsystem.
/// When false (the v4.0 default), tool-result compression,
/// conversation compaction, and CCR are all skipped, regardless
/// of the per-feature flags below. The kill switch.
compression_enabled: bool = false,
```

#### CLI flag

```
--compression / --no-compression
  Enable or disable the entire compression subsystem (master switch).
  Default: off (no behavioural change from v3.x).
  Examples:
    franky --compression                    # enable all compression
    franky --no-compression                 # disable all compression
    franky --compression --compact-after 50 # enable compression + tune compaction
```

The per-feature CLI flags from §6.2 (`--compress-tool-results`,
`--compact-after <N>`, `--ccr-store <path>`) remain in place and are
**shortcuts that implicitly enable the master switch**: passing
`--compress-tool-results` is equivalent to passing
`--compression --compress-tool-results=true`. This way a user can
opt in to a single feature without remembering the master switch, and
the master switch is reserved for "kill it entirely".

### 6.1 New Config Fields in `Agent.Config`

```zig
// src/agent/types.zig additions:

/// v4.0 — master switch for the entire compression subsystem.
/// When false, all per-feature flags below are ignored. See §6.0.
compression_enabled: bool = false,

/// v4.0 — Enable content-aware tool result compression.
/// Only consulted when `compression_enabled` is true.
/// When true, tool outputs are passed through zompress before entering
/// the conversation history. Default: false.
compress_tool_results: bool = false,

/// v4.0 — Conversation compaction threshold.
/// Only consulted when `compression_enabled` is true.
/// When the transcript exceeds this many messages, older messages are
/// compressed into a single "compaction_summary" message. 0 disables.
compact_after_messages: u32 = 0,

/// v4.0 — Number of most recent messages to protect from compaction.
compact_protect_recent: u32 = 8,

/// v4.0 — Path to optional on-disk CCR store.
/// Only consulted when `compression_enabled` is true.
ccr_store_path: ?[]const u8 = null,

/// v4.0 — Cap on CCR store entries (FIFO eviction beyond this).
ccr_max_entries: u32 = 10_000,

/// v4.0 — Reference to optional CCR session (set by agent init).
ccr_session: ?*CcrSession = null,
```

### 6.2 CLI Flags

> ✓ decided: CLI flags use **kebab-case with double-dash** (the existing
> convention shown in the doc: `--compress-tool-results`, `--compact-after`,
> `--ccr-store`). The internal `Agent.Config` fields stay in Zig's
> `snake_case` (`compress_tool_results`, etc.) and a thin
> `flags.zig` parser maps one to the other. This matches what the rest
> of franky's CLI already does and what users coming from `claude`,
> `gemini`, `codex`, etc. expect.

```zig
// In the CLI argument parser:

// --compression / --no-compression
//   Master switch for the entire compression subsystem. Default: off.
//   Passing any per-feature flag below implicitly enables the master switch.

// --compress-tool-results
//   Enable content-aware compression of tool outputs.
//   Default: off (no behavioural change).

// --compact-after <N>
//   Compact conversation history after N messages.
//   Default: 0 (off). Example: --compact-after 50

// --ccr-store <path>
//   Enable Compress-Cache-Retrieve with on-disk persistence at <path>.
//   Default: none (CCR disabled). Example: --ccr-store ~/.franky/ccr.db
```

### 6.3 Default Behaviour

**Compression defaults to OFF** — the master switch
(`compression_enabled`) is `false` by default, and the per-feature
flags all default to off/0/null. With all defaults the existing 8 KiB
flat truncation is preserved. Users opt in either via the master
switch (`--compression` / `"compression": { "enabled": true }`) or
implicitly by passing any per-feature flag. This is critical for a
safe rollout:

```zig
// franky's Config → zompress CompressConfig mapping:
const effective_compress = config.compression_enabled and config.compress_tool_results;
const zompress_config: zompress.CompressConfig = if (effective_compress) .{
    .smart_crusher_enabled = true,
    .log_compressor_enabled = true,
    .search_compressor_enabled = true,
    .diff_compressor_enabled = true,
    .min_tokens_to_compress = config.min_tokens_to_compress,
} else .{
    .smart_crusher_enabled = false,
    .log_compressor_enabled = false,
    .search_compressor_enabled = false,
    .diff_compressor_enabled = false,
    .min_tokens_to_compress = std.math.maxInt(usize), // effectively off
};
```

### 6.4 `settings.zig` Wiring

A new `applyCompressionSection()` follows the existing pattern
(§tools, §permissions, §review) in `src/coding/config/settings.zig`:

```zig
fn applyCompressionSection(settings: *Settings, obj: std.json.ObjectMap) !void {
    if (obj.get("compression")) |c_v| if (c_v == .object) {
        if (c_v.object.get("enabled")) |e| if (e == .bool) {
            settings.compression_enabled = e.bool;
        };
        if (c_v.object.get("min_tokens_to_compress")) |m| if (m == .integer and m.integer >= 0) {
            settings.min_tokens_to_compress = @intCast(m.integer);
        };
    };
}
```

### Acceptance Check

| Settings / Flags | Expected Behaviour |
|------------------|-------------------|
| No flags, no `compression` block | Existing 8 KiB truncation, no compaction, no CCR |
| `--compression` | Master switch on; per-feature defaults still off → no compression, but master is "on" |
| `--compression --compress-tool-results` | Tool outputs compressed by zompress |
| `--compression --compact-after 50` | History compacted after 50 messages |
| `--compression --ccr-store /tmp/ccr` | CCR persists to /tmp/ccr |
| `--no-compression --compress-tool-results` | Per-feature flag is **ignored**; no compression runs (master wins) |
| All flags combined | Full pipeline active |
| `settings.json` has `"compression": { "enabled": false }`, no CLI flag | Master switch off, no compression |
| `settings.json` has `"compression": { "enabled": true }`, CLI `--no-compression` | CLI wins → no compression |


### 7.2 Per-Turn Stats

> ✓ decided: telemetry records **three** counters, not two:
> `compress_attempted` (every call to `zompress.compress` for a tool
> result), `compress_applied` (those that produced a smaller output than
> the 8 KiB cap would have), and `compress_skipped_uneconomical` (those
> that ran but lost the byte-length comparison). The third bucket is
> what tells you whether `min_tokens_to_compress` is set too low for your
> workload.

Add a `CompressionStats` struct that accumulates across turns:

```zig
pub const CompressionStats = struct {
    total_input_bytes: u64 = 0,
    total_output_bytes: u64 = 0,
    total_tokens_saved: u64 = 0,
    compress_count: u32 = 0,
    compaction_count: u32 = 0,
    ccr_stores: u32 = 0,
    ccr_retrievals: u32 = 0,

    pub fn ratio(self: CompressionStats) f64 {
        if (self.total_input_bytes == 0) return 1.0;
        return @as(f64, @floatFromInt(self.total_output_bytes)) /
               @as(f64, @floatFromInt(self.total_input_bytes));
    }
};
```

At session end, emit a summary:

```
[Compression stats]
  Tool results compressed: 47
  Bytes saved: 1.2MB / 1.5MB (80% reduction)
  Conversation compactions: 3
  CCR stores: 47 | CCR retrievals: 2
  Estimated token savings: ~285,000 tokens (~$1.42 at Sonnet rates)
```

## 10. Risk Assessment

| Risk | Impact | Probability | Mitigation |
|------|--------|-------------|------------|
| Compression increases token count on small inputs | Wasted cycles | Low | `min_tokens_to_compress = 100`, compare lengths before/after |
| CCR store memory grows unbounded | OOM | Medium | Per-session limit (configurable), oldest-eviction policy |
| Compaction drops critical context | Bad model responses | Medium | `compact_protect_recent = 8` (tunable), CCR for retrieval |
| Content detection misclassifies input | Wrong compressor applied | Low | Falls through to plain_text → 8 KiB cap (no data loss) |
| Race condition on concurrent tool calls | Corrupted CCR state | Low | Use `std.HashMap` with arena allocator (append-only during turn) |
| AST parser rejects valid Zig | Code passthrough | Low | `code_compressor` falls back to passthrough on parse errors |
| Model doesn't understand compressed output | Poor quality | Medium | Add `// ... N lines omitted ...` markers; train on examples |
| Regression in existing 8 KiB truncation path | User-facing bug | Critical | `compress_tool_results=false` by default; integration test compares output |
| Memory allocation in hot path (every tool call) | Latency spike | Medium | Arena allocator per-turn; free at turn boundary |
| User can't easily disable compression after a regression | Wasted debugging time | Medium | Master `compression.enabled` switch in `settings.json` + `--no-compression` CLI flag (§6.0); per-feature flags are gated by the master so a single kill switch turns off the whole subsystem |

### Backward Compatibility Guarantee

**With `compression_enabled = false` (the default), zero lines of existing
behaviour change.** No new dependencies, no new allocations, no new code paths
executed. The per-feature flags (`compress_tool_results`,
`compact_after_messages`, `ccr_store_path`) are also off by default, so even
a user who *does* set `compression_enabled = true` and forgets the rest
gets the original 8 KiB truncation. Users who never opt in are unaffected.
