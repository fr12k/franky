# v2.7 — Subagent Panel (compact list + full overlay)

**Status:** implemented
**Affects:** `src/coding/modes/proxy.zig`, `src/coding/modes/web/index.html`, `src/coding/modes/web/style.css`, `src/coding/modes/web/app.js`

## Problem

v2.6 inline progress log shows sub-agent activity as flat truncated (60-char) text entries. No way to read full sub-agent output.

## Goals

1. Full sub-agent conversation (markdown, thinking, tool calls) on demand without consuming screen width.
2. Support multiple concurrent/past sub-agents; each gets a right-side panel entry.
3. Two entry points: click panel row, or click `↗` in inline tool card.
4. Keep main conversation uncluttered — panel is compact index.
5. No wire-protocol changes; reuse `tool_execution_update` SSE events.

## Design decisions

| Question | Decision |
|---|---|
| Panel width | 220 px — compact list, title + badge only |
| Content view | Full-screen overlay, opened by clicking panel row or ↗ card link |
| Overlay closes | × button or clicking backdrop |
| Panel auto-opens | Yes — on first `tool_execution_start` for `subagent` call |
| Live updates while overlay open | Yes — new events update overlay DOM directly |
| Thinking display | Collapsible block; auto-expands while streaming, collapses on completion |
| Finished sections | Persist for session; overlay can be reopened any time |
| Sections cleared on `/clear` | Yes |
| RPC / interactive modes | No change — panel is proxy (web UI) only |

## Architecture

**Data flow:**
```
subagent tool call starts
  └─ startToolCall("subagent", callId, argsJson)
        ├─ attachSubagentPanel(card.el, callId)  ← inline log + ↗ link
        └─ createSubagentSection(callId, argsJson)  ← compact panel row

sub-agent running
  └─ SSE: tool_execution_update {callId, update}
        ├─ appendSubagentEntry(card, log, upd)       ← existing inline log
        └─ appendSubagentPanelEvent(callId, upd)     ← accumulates + live overlay

subagent tool call ends
  └─ endToolCall(callId, isError, ...)
        └─ finalizeSubagentSection(callId, isError)  ← badge update
```

**`verbose_progress`:** `text_delta`/`thinking_delta` forwarded to SSE only when `ctx.verbose_progress = true`. Set to `true` in `proxy.zig` for subagent context.

**Per-section state object:** Content accumulated in JS state so overlay can be opened/re-opened any time. Fields: `preset`, `argsJson`, `textBlocks` (Map), `thinkingBlocks` (Map), `eventLog` (Array), `rowEl`, `badgeEl`, `done`, `isError`.

**Overlay state:** Single overlay element reused; `currentOverlayCallId` tracks active call. New events for active call append directly to overlay DOM.

**Layout:**
```
#layout (flex row)
  aside#sidebar            ← left 220px
  div#main-pane            ← flex:1
    main#conversation
      .tool-card           ← ↗ link in top-right corner
    #composer-wrap
  aside#subagent-panel     ← right 220px, compact list
    .sa-panel-head
    #subagent-panel-body   ← one .sa-row per call, clickable

<div id="sa-overlay">      ← fixed overlay, outside layout
  .sa-overlay-backdrop     ← click-to-close
    .sa-overlay-card       ← 80vw × 80vh, flex column
      .sa-overlay-head     ← badge + preset name + close ×
      .sa-overlay-body     ← thinking + text + tool entries
```

## Non-goals

- Interactive mode / RPC mode: no SSE bus, no panel.
- Panel state persistence across page reload.
- Nested sub-agents (depth > 1 prevented by tool exclusion).
- Multiple overlays simultaneously.
