# v2.8 — Edit Tool Diff View

**Status:** shipped — 2026-04
**Affects:** `src/coding/tools/edit.zig`, `src/agent/proxy.zig`, `src/coding/modes/web/app.js`, `src/coding/modes/web/style.css`, `src/coding/modes/web/index.html`
**Depends on:** v2.7 subagent panel (overlay infrastructure already in place)

---

## 1. Problem

Edit tool returns plain-text line-diff — no color coding, no line numbers, no file context, no word-level highlighting. Users need a visual diff (like GitHub/GitLab) to quickly understand what changed and where.

---

## 2. Goals

1. Visual diff in tool card when `edit` completes — colored additions/deletions, line numbers, file path header.
2. Support unified (line-by-line) and side-by-side views with toggle.
3. Preserve existing text summary for model's context window — diff view is enhancement, not replacement.
4. Zero build-step overhead — plain JS, CDN-loaded diff2html.
5. Reuse existing tool-card infrastructure.
6. No wire-protocol changes — reuse `details_json` (already on `ToolResult`); add `detailsJson` to `tool_execution_end` SSE frame.
7. Syntax highlighting for code in diff (optional, high value).

---

## 3. Design decisions

### Q1: Where to compute diff — server vs client?
**Decision:** ✅ Server generates unified diff string. `edit.zig` builds proper unified diff (original ↔ final), sends in `details_json`. Client renders with `diff2html`. Cleaner separation, lighter client.

### Q2: Diff algorithm on server
**Decision:** Minimal LCS-based line diff in Zig (~100 LOC). Simple DP LCS fine for <1000-line files. Produces standard unified diff with 3 context lines.

### Q3: How to deliver diff to client
`details_json` on `ToolResult` (already exists): `{"diff": "@@ ... @@", "path": "src/main.zig"}`. Add `detailsJson` to `tool_execution_end` SSE encoding in `proxy.zig`.

### Q4: Side-by-side vs unified default
**Decision:** Default to **unified (line-by-line)** with toggle button for side-by-side. diff2html supports both via `outputFormat`.

### Q5: Auto-expand vs collapsed
**Decision:** **Always auto-expand** result panel for `edit` tool calls. For non-edit tools, keep collapsed-by-default.

### Q6: Rehydration
**Decision:** **Option A** — store `details_json` in transcript messages alongside `ToolResult`. For v2.8 initial, Option C (graceful fallback to plain text on rehydration) acceptable as minimum.

### Q7: TUI (terminal) diff view
**Decision:** Defer to future version. TUI already has ANSI diff renderer for screen-buffer layer; conversation-pane diff needs separate design.

## 4. Architecture

### 4.1 Data flow

```
edit tool called
  ├─ read file → original_text
  ├─ apply edits → final_text
  ├─ computeUnifiedDiff(original_text, final_text)
  ├─ return ToolResult { content[0].text = plain text, details_json = {"diff":"...","path":"..."} }
  └─ loop.zig encodes tool_execution_end SSE event
       └─ proxy.zig → includes detailsJson in SSE payload

tool_execution_end received in app.js
  ├─ endToolCall(callId, isError, toolCode, resultText, detailsJson)
  ├─ detect edit tool by detailsJson.diff exists
  │   ├─ YES → renderEditDiffView(panel, detailsJson)
  │   │         └─ diff2html renders unified diff → HTML inserted into panel
  │   └─ NO  → plain text (current behavior)
```

### 4.2 Server-side: `computeUnifiedDiff` in `edit.zig`

Splits both texts into lines, computes LCS (O(n*m) DP for n,m ≤ 2000), traces back to find changed regions, emits standard unified diff format (`--- a/<path>`, `+++ b/<path>`, `@@ -start,count +start,count @@`, context, `-removed`, `+added`). 3 context lines around each hunk. Falls back gracefully on failure: `{"diff": null, "path": "..."}`.

### 4.3 Server-side: SSE encoding (`proxy.zig`)

Add `detailsJson` to `tool_execution_end` SSE frame. `details_json` is already valid JSON — append directly without re-encoding.

### 4.4 Client-side: `index.html`

Add diff2html CDN scripts before `app.js`:
```html
<script src="https://cdn.jsdelivr.net/npm/diff2html/bundles/js/diff2html.min.js"></script>
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/diff2html/bundles/css/diff2html.min.css">
```

### 4.5 Client-side: `style.css`

Overrides: `.tool-card.is-edit .tool-result-log` (zero padding, horizontal scroll), `.d2h-file-header` hidden, `.d2h-code-line` compact padding, `.diff-view-toggle` button styling, dark-theme compatibility.

### 4.6 Client-side: `app.js` changes

- **SSE handler:** Pass `detailsJson` to `endToolCall()`.
- **`endToolCall`:** Check `detailsJson.diff` → call `renderEditDiffView()`; else fall back to plain text.
- **`renderEditDiffView(cardEl, panelEl, toggleEl, details)`:** Adds `is-edit` class, auto-expands panel, adds view-toggle button (unified ↔ side-by-side), calls `renderDiff()`.
- **`renderDiff(panelEl, diffString, mode, filePath)`:** Configures `Diff2Html.html()` with `outputFormat`, renders, applies syntax highlighting if `hljs` available. Falls back to plain text on error.
- **`startToolCall`:** Add `is-edit` class early when name === 'edit'.
- **`appendFinalizedToolCard`:** Accept `detailsJson` param for rehydration; render diff if available.

### 4.7 State management

No new persistent state. Diff string self-contained in `detailsJson`. View-toggle mode is per-card local variable.

## 6. Edge cases & non-goals

### Edge cases

| Case | Handling |
|---|---|
| Edit fails (no_match, ambiguous) | `is_error=true`, no `details_json`, red card + error text |
| Empty file | `edit_file_empty` error — no diff |
| Single-line edit | Unified diff shows one-line hunk with context |
| Whitespace-only changes | diff2html highlights changed whitespace |
| Very large file (>2000 lines) | Cap LCS table; fall back to before/after dump |
| Binary-ish content | Skip diff, show plain text |
| Multiple edits in one call | LCS handles all changes — one unified diff |
| Page reload | Fall back to plain text (no `details_json` in transcript yet) |
| CDN load failure | `typeof Diff2Html === 'undefined'` → plain text |
| Dark theme mismatch | Override `.d2h-code-line-*` colors |

### Non-goals

- TUI terminal diff — deferred.
- Interactive diff review (accept/reject individual edits).
- Diff persistence across page reload (acceptable for v1).
- Word-level diff highlighting (default `matching: 'lines'`; revisit if requested).
