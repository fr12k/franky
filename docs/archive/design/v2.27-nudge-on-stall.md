# v2.27 — Nudge stalled models (Option A)

**Status:** ✅ Implementation complete  
**Implemented:** 2026-05-13  

## Problem

GPT-family models occasionally stop generating mid-thought — SSE stream ends with `stop_reason=length` (token cap) or `stop_reason=stop` with very little/no content. No standard way to inject nudge mid-stream (HTTP is fire-and-forget). Only option: inject synthetic user message between turns and call LLM again.

## Approach — Option A

Inject nudge in agent loop, between `runTurn()` returning `false` and existing `between_turns` hook. Nudge is `.user`-role message: "continue from where you left off." Loop runs another turn transparently.

### Detection

After `runTurn` returns `false`, inspect last assistant message:

| Signal | Action |
|---|---|
| `stop_reason == .length` | **Strong** — model hit token cap mid-generation |
| `stop_reason == .stop` AND no tool calls AND total text < ~50 chars | **Moderate** — stopped with near-empty output |
| `stop_reason == .stop` AND zero text content (degenerate) | **Moderate** — empty response |
| `stop_reason == .tool_use` | **Skip** — model is productive |
| `stop_reason == .refusal` / `.err` / `.aborted` | **Skip** — intent was to stop or error |

### Nudge messages

| Trigger | Nudge text |
|---|---|
| `stop_reason == .length` | "You were cut off mid-response (token limit reached). Continue from where you left off." |
| Degenerate / near-empty `.stop` | "Your response was very brief. Please continue or elaborate." |

### Guard — nudge limit

At most **2 nudges per stall episode**. Counter `nudge_count` on agent loop stack, resets implicitly on loop restart. After 2 nudges, loop lets turn end naturally.

### Config

Add to `loop.Config`: `nudge_on_stall: bool = false` (default `false` — no behavioural change for existing callers). Mode drivers opt in.

## Integration sketch

In `agentLoop`, right before `between_turns` hook:

```
runTurn returns false
├─ guardrails.betweenTurns → false
├─ v2.27 [nudge_on_stall]:
│  ├─ inspect last transcript message
│  ├─ if stalled AND nudge_count < 2:
│  │  ├─ nudge_count += 1
│  │  ├─ append "continue" user message to transcript
│  │  └─ continue (run another turn)
│  └─ else: fall through
├─ between_turns hook
├─ out.close / return
```

## Test plan

Tests in `test/agent_loop_test.zig`:

1. **`stop_reason=length` triggers nudge** — faux emits text + `.length`, `nudge_on_stall=true`. Expect: nudge injected, second turn runs, transcript has 3 messages.
2. **Degenerate `.stop` triggers nudge** — faux emits zero text blocks, `stop_reason=.stop`. Same outcome.
3. **Nudge cap (max 2)** — faux emits three scripts all with `stop_reason=length`. Loop nudges twice, third turn ends naturally.
4. **`nudge_on_stall=false` (default) — no nudge** — faux emits `.length`, default config. Loop ends after 1 turn.
5. **Tool calls skip nudge** — faux emits tool_call + `.tool_use`, `nudge_on_stall=true`. Loop executes tool and returns, no nudge.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Infinite nudge loop | Cap at 2 nudges then fall through |
| False positive on short but complete answers | Threshold ~50 chars + no terminal punctuation check |
| Nudge message visible in UI | It's `.user` transcript message — currently user messages aren't streamed as events by loop |
| Nudge delays steer/followUp by up to 2 turns | Acceptable — nudge is fast; steer queue drained on next non-nudge turn |
