# v2.16 — Multi-Model Code Review

**Status:** implemented — all acceptance criteria met
**Affects:** `src/coding/tools/subagent.zig`, `src/coding/skills.zig`, `src/coding/settings.zig`
**Related:** v2.14 (Agentic Engineering)

---

## 1. Problem

`/simplify` parallelises review across 3 agents, but each runs on the **same model** with different focus dimensions. Diversity comes from prompt, not model. Different models have different training distributions and failure modes — a bug one model overlooks may be caught by another. Cross-model agreement increases finding confidence.

**Gap:** no mechanism to run same review across multiple models and surface findings by cross-model confidence.

---

## 2. What already exists

| Primitive | What it provides |
|---|---|
| `subagent` tool | Spawn N isolated agents in parallel, each with own model profile and system prompt |
| `code-audit` preset | Read-only workspace agent, structured finding output. Default profile `ollama-gemma4` |
| Profile system (`settings.json`) | Named model configs with provider, API key, timeout overrides |
| franky skill files (`~/.franky/skills/`) | Markdown files injected into system prompt; can instruct parent model |

`subagent` tool already supports `profile` override per call — parent can spawn 3 subagents on 3 different profiles in one fan-out. v2.16 makes this pattern **discoverable, configurable, and aggregation-aware**.

---

## 3. Proposed mechanism

### 3.1 Trigger

Skill file `~/.franky/skills/multimodel-review.md` activated on `/review`. Instructs model to:
1. Collect review target (default: `git diff HEAD`).
2. Read configured review profiles (`settings.json` → `review.profiles`).
3. Spawn one `code-audit` subagent per profile in single parallel fan-out.
4. Wait for all results.
5. Synthesise unified report with per-finding confidence labels.

### 3.2 Model selection

Priority order:
1. Invocation argument — `/review --profiles gemini,deepseek,claude` (per-run override).
2. `review.profiles` in `settings.json` — user's declared set.
3. Auto-discovery fallback — all profiles with `capabilities.code_generation = true` and configured API key, max 4.

Default: 3 built-in presets whose API keys are present at session start.

### 3.3 Review dimensions

Each model gets identical "find all code issues" prompt. Diversity purely from model. Aggregation purely about finding overlap.

### 3.4 Aggregation

Parent model:
1. Reads all N reports.
2. Groups semantically equivalent findings (same file, same concern).
3. Labels: `[all N]` (high confidence), `[N-1 of N]` (medium-high), `[1 of N]` (low/disputed).
4. Produces unified report sorted by confidence descending.

### 3.5 Failure handling

If one subagent errors/times out, run does NOT abort — remaining reports still aggregated. Report notes which profiles produced no output. `min_models` setting (default 2) aborts if fewer than that many models completed.

## 7. Decisions

### Q7.1 — Same prompt vs. rotated dimensions?
**Decided:** Same prompt (Option A). Model diversity already provides dimension diversity implicitly.

### Q7.2 — LLM aggregation vs. rule-based dedup?
**Decided:** LLM aggregation using parent model. Parent has full context; aggregation prompt is small.

### Q7.3 — Skill file vs. built-in command?
**Decided:** Skill file (`~/.franky/skills/multimodel-review.md`). User-editable, keeps core lean. Promote to built-in if parameter surface gets complex.

### Q7.4 — Where does `review` config live?
**Decided:** `review: { profiles, min_models, max_models, timeout_ms }` namespace in `settings.json`.

### Q7.5 — Default review target?
**Decided:** `git diff HEAD` (staged + unstaged) — same as `/simplify`. Caller can pass explicit path/diff.

### 8.2 Phase 1 — `settings.zig` (~35 lines)

New fields: `review_profiles: [][]const u8`, `review_min_models: u32 = 2`, `review_max_models: u32 = 4`, `review_timeout_ms: u64 = 180_000`. `deinit` adds `deinitStringArray` call. `applyLayer` JSON parser adds `"review"` block handling.

### 8.3 Phase 2 — `cli.zig` (~5 lines)

Add `review_config_block: ?[]const u8 = null` to `Config`. Populated programmatically by mode drivers, not CLI flag.

### 8.4 Phase 3 — `skills.zig` + skill file (~70 lines)

`BuiltinSkill` struct with `name` + `content` (`@embedFile`). `loadAll` appends builtins after existing roots loop — only if name not already loaded (user file overrides builtin). Skill file content: frontmatter + process instructions (collect diff, select profiles, fan out, check quorum, aggregate, render).

### 8.5 Phase 4 — Mode drivers (~15 lines each)

Populate `review_config_block` in `runPrint` (and equivalent in interactive/proxy/rpc): join profiles with ", ", format `## Review configuration` block with profiles/min_models/max_models/timeout_ms. Inject in `buildSystemPromptIo` after skills section, only if multimodel-review skill is active.

**Preferred:** Single `review_config_block: ?[]const u8` field on `cli.Config` — keeps all four values out of `cli.Config` (single opaque string), `buildSystemPromptIo` stays unaware of review semantics.

### 8.6 Acceptance criteria

| # | Criterion |
|---|---|
| A1 | `settings.json` with `"review": {"profiles": ["a","b"]}` parses into `Settings.review_profiles` |
| A2 | Two-layer settings (user + project) → concatenation, not replacement |
| A3 | `--skill multimodel-review` activates builtin when no user file exists |
| A4 | User `~/.franky/skills/multimodel-review.md` overrides builtin (name dedup) |

| A8 | One subagent errors, `min_models=2`, only 1 responds → model aborts with quorum message |
| A9 | Unified report groups findings by confidence tier, sorted high → low |
