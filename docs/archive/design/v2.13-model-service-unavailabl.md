# v2.13 — Hosted Model Service Unavailability (Phases 1+2)

**Status:** implemented — Phases 1 (observability) and 2 (tunable retry budget) complete
**Phase 3** (fallback model chain) tracked separately in [`v2.13b-fallback-model-chain.md`](../decided/v2.13b-fallback-model-chain.md)
**Affects:** `src/ai/retry.zig`, `src/ai/stream.zig`, `src/coding/settings.zig`, `src/coding/cli.zig`

## Problem

Hosted providers go down. Before v2.13, agent surfaced terminal error after transport-layer retry budget exhausted. For unattended sibling apps, the run died and work item ended in "failed — provider error."

## Goal

Agent loop should back off and retry; handle gracefully without crashing or infinite loop. User informed about issue and retry attempts.

Two asks: (1) Better retry behaviour — longer-running, visible, no crash on sustained outages. (2) Fallback model chain — declared in `settings.json`; on primary exhaustion, switch to next provider. _(Phase 3 — tracked separately.)_

## What franky already had

### `src/ai/retry.zig` — transport-layer retry
- `Policy{ max_retries: u32 = 3, base_delay_ms: u32 = 500, max_retry_delay_ms: u32 = 60_000 }`
- Decorrelated-jitter exponential backoff: `delay = min(max_retry_delay_ms, random(base, prev * 3))`
- `Retry-After` header takes precedence when ≤ `max_retry_delay_ms`
- Hard invariant: **never retry once response bytes have started flowing** (§F.1)
- Cancel-fired short-circuit before each attempt and sleep

### `src/ai/errors.zig` — error classification
`Code` enum with `isRetryable()` returning true for `.rate_limited`, `.transient`, `.timeout`, `.transport`.

## Gaps addressed

### Retry budget too small for unattended use
`max_retries: 3` with `max_retry_delay_ms: 60_000` → ~3 min total. Now policy-driven via `retry_max_attempts` and `retry_max_total_ms` in settings.

### Retry invisible to the harness
Retry loop slept silently. Phase 1 adds `provider_retry` stream event emitted before each sleep.

## Implementation

### Phase 1 — Observability (`provider_retry` stream event)

**`src/ai/stream.zig`** — new variant: `provider_retry` struct with `attempt`, `max_attempts`, `delay_ms`, `reason` (errors.Code), `provider_code`, `provider_message`, `http_status`. Emitted by `retry.run()` **before the sleep**, at verdict flip to `.retryable`. Propagates through channel/Reducer paths → TUI shows "retrying in 4s (attempt 2/3)…", proxy SSE carries it, sibling apps subscribe.

### Phase 2 — Tunable retry budget

**`src/coding/settings.zig`** — new fields: `retry_max_attempts: ?u32`, `retry_max_total_ms: ?u64`. Parsed from `settings.json` under `tools.retry.{maxAttempts, maxTotalMs}`.

**`src/coding/cli.zig`** — new flags: `--retry-max-attempts N`, `--retry-max-total-ms N`. CLI wins over settings.json.

**`src/ai/retry.zig`** — `Policy.max_total_delay_ms`: `retry.run()` tracks accumulated `total_delay_ms`. Before each sleep, if `total_delay_ms + next_delay_ms > max_total_delay_ms` → emit terminal with `rate_limited_hard` and `retry_after_ms` set to remaining budget.

**Profile presets:** `"agent-unattended"` profile with `retry_max_attempts: 15`, `retry_max_total_ms: 1800000` (30 min).

## Decisions

| Q | Decision |
|---|---|
| Q1 — Default `retry_max_total_ms` | Keep ~3 min for interactive default; unattended profiles opt in explicitly |
| Q2 — `provider_retry` timing | Before-sleep, at verdict flip. UI gets advance notice while sleep runs |
| Q4 — 429 vs 503 | Unified: honour `Retry-After` for both; phase-3 fallback handles either exhaustion |
| Q5 — Mid-stream 503 | Keep §F.1 invariant; add `mid_stream: true` field to `error_ev` for sibling disambiguation |

## Out of scope

- API key / credential management (deferred to v3)
- Per-tool retry (separate concern)
- Caching responses
- Provider health dashboard in web UI
- Fallback model chain (Phase 3 — see `v2.13b-fallback-model-chain.md`)
