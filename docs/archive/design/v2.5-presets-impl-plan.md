# v2.5 presets — implementation plan

**Status:** shipped

Companion to `v2.5-presets.md`. Step-by-step build sequence with file targets and acceptance criteria. ~300 LOC in subagent.zig + ~50 LOC across four mode drivers.

---

## Step 1 — `SafetyClaims` + `Preset` + `PresetRegistry` types

**File:** `src/coding/tools/subagent.zig`

Add three structs before `Ctx`: `SafetyClaims` (max_result_bytes, read_only, requires_sandbox, max_calls_per_minute), `Preset` (name, description, default_profile, default_role, default_system_prompt, build_tools fn, safety), `PresetRegistry` (StringArrayHashMapUnmanaged, init/deinit/register/get/names). `register` logs warn on override.

**Acceptance:** `zig build test` passes; types visible via `@import("tools/subagent.zig").Preset`.

---

## Step 2 — Built-in preset catalog

**File:** `src/coding/tools/subagent.zig`

`registerBuiltinPresets` after registry type. Four built-ins:

| Preset | Tools | default_profile | default_role |
|---|---|---|---|
| `research` | read, ls, find, grep | `gemini` | read |
| `code-audit` | read, ls, find, grep | `gemini` | read |
| `file-ops` | read, write, edit, ls | `""` (inherit parent) | plan |
| `bash-runner` | bash, ls | `""` (inherit parent) | code |

**Decision:** Filter tools from `parent_tools` (wired with workspace/state), not bare factories. `selectTools` helper matches by name. `""` default_profile signals "inherit parent's profile."

**Acceptance:** Unit test case 1 — registry contains all four presets with correct fields.

---

## Step 3 — Dynamic `parameters_json` + `buildParametersJson`

**File:** `src/coding/tools/subagent.zig`

Replace static `parameters_json` with `buildParametersJson(allocator, registry)` — builds enum array from registry.names(). Store on `Ctx` as `parameters_json_owned`. `toolWithCtx` reads from ctx.

**Acceptance:** Test case 2 — enum contains exactly registered preset names.

---

## Step 4 — Wire preset into `runSubagent`

**File:** `src/coding/tools/subagent.zig`

### 4a — `ParsedArgs`
Add `preset: []const u8` (required). Profile becomes optional (falls back to preset's `default_profile`). Missing preset → `error.MissingPreset` → `invalid_args`.

### 4b — Preset lookup
Look up in `ctx.presets`; not found → `preset_not_found` error with hint to call `list_subagent_presets`.

### 4c — Role check
Effective role = `parsed.role orelse preset.default_role`. If `!ctx.parent_role.atLeast(effective_role)` → `role_promotion_denied` with hint naming preset and required role.

### 4d — Effective profile
`parsed.profile orelse (preset.default_profile if non-empty else ctx.parent_profile)`. Add `parent_profile: []const u8` to `Ctx`.

### 4e — Build sub-agent tool list
Replace "copy parent_tools minus subagent" with `preset.build_tools(allocator, ctx.parent_tools)`.

### 4f — Effective system prompt
`parsed.system_prompt orelse preset.default_system_prompt`.

### 4g — `max_result_bytes` truncation
After sub-agent completes, apply `truncateHead` when `preset.safety.max_result_bytes != null`.

**Acceptance:** Test cases 3 (dispatch), 7 (role), 8 (truncation).

---

## Step 5 — `list_subagent_presets` tool

**File:** `src/coding/tools/subagent.zig`

New tool factory `listPresetsToolWithCtx(registry)` — returns JSON array of all registered presets with name, description, default_profile, default_role, safety fields. Static schema (no args).

**Acceptance:** Test case 4 — returns all registered presets.

---

## Step 6 — Mode driver wiring (4 files)

**Files:** `src/coding/modes/print.zig`, `proxy.zig`, `rpc.zig`, `interactive.zig`

Each mode, at session-init:
1. Init `PresetRegistry`, call `registerBuiltinPresets`
2. Build dynamic `parameters_json` via `buildParametersJson`
3. Wire into `subagent.Ctx` (presets, parameters_json_owned, parent_profile)
4. Add `listPresetsToolWithCtx` alongside `subagent` tool in final_tools

**Acceptance:** Integration smoke-test — `list_subagent_presets` returns 4 built-ins.

---

## Step 7 — Tests

**File:** `src/coding/tools/subagent.zig` (existing test block)

Eight test cases:
1. `registerBuiltinPresets` populates all four with correct defaults
2. `buildParametersJson` enum = `["research","code-audit","file-ops","bash-runner"]`
3. Faux sub-agent: `preset:"research"` → tool list = [read, ls, find, grep] only
4. `executeListPresets` returns JSON array with all 4
5. SDK custom preset: registered → appears in enum + dispatch invokes builder
6. Collision: re-register `"research"` → warn log, new definition wins
7. Role promotion denied: parent=read, preset=code → `role_promotion_denied` with hint
8. `max_result_bytes=10`, 100-byte result → truncated to ≤10 bytes
