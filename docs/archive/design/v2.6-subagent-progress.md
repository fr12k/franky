# v2.6 — SubAgent Tool Execution Progress

**Status:** decided — ready for implementation  
**Affects:** `src/coding/tools/subagent.zig`, `src/agent/proxy.zig`, `src/coding/modes/proxy.zig`, `src/coding/modes/rpc.zig`, `src/coding/modes/web/app.js`, `src/coding/modes/web/style.css`  
**Deferred to v3:** interactive mode progress display

---

## 1. Problem

When parent agent calls `subagent` tool, user sees "tool: subagent running…" then silence for minutes. Parent's event stream shows nothing until `tool_execution_end`. Especially visible in web UI (proxy mode).

---

## 2. Goals

1. Surface sub-agent progress without modifying parent's context window (no new Transcript messages)
2. Reuse existing wire protocol — no new SSE event types
3. Web UI: collapsible, hidden by default
4. Work in proxy and rpc modes. Interactive deferred to v3. Print skipped (no event bus)

---

## 3. Architecture

### 3.1 `Agent.subscribe` — the tap point

`Agent` already exposes `subscribe(handler, userdata)` / `unsubscribe(id)`. Handler fires synchronously from sub-agent's worker thread for every `AgentEvent`. No changes to `agentLoop` required.

### 3.2 `tool_execution_update` — the carrier

`AgentEvent.tool_execution_update` already exists: `{ call_id, update_json }`. Sub-agent progress encoded into `update_json` as opaque JSON blob.

### 3.3 `progress_fn` and `verbose_progress` in `subagent.Ctx`

Add three fields to `subagent.Ctx`:
- `progress_fn: ?*const fn (userdata, call_id, update_json) void` — called from sub-agent worker thread; must be thread-safe
- `progress_userdata: ?*anyopaque`
- `verbose_progress: bool = false` — when true, also forward text/thinking deltas

In `runSubagent`, before `sub_agent.prompt(...)`: create `ForwardState`, subscribe if `progress_fn != null`, defer unsubscribe.

### 3.4 Events forwarded

| Sub-agent event | Forwarded? | `update_json` shape |
|---|---|---|
| `turn_start` | always | `{"kind":"turn_start","turn":N}` |
| `tool_execution_start` | always | `{"kind":"tool_start","name":"X","cid":"Y"}` |
| `tool_execution_end` | always | `{"kind":"tool_end","name":"X","cid":"Y","ok":true}` |
| `turn_end` | always | `{"kind":"turn_end","turn":N}` |
| `agent_error` | always | `{"kind":"error","msg":"..."}` |
| `message_update` text | only when `verbose_progress` | `{"kind":"text_delta","block":N,"delta":"..."}` |
| `message_update` thinking | only when `verbose_progress` | `{"kind":"thinking_delta","block":N,"delta":"..."}` |
| `message_start/end` | never | no user value |
| `tool_execution_update` | never | no nested forwarding |

All `kind` values use readable names.

### 3.5 Thread safety

`subagentProgressHandler` fires from sub-agent's worker thread. `broadcastEvent` in `proxy.zig` must hold mutex for full duration of stamp + ring-write + fan-out. **Verify before wiring; add concurrent-broadcast test.**

### 3.6 `update_json` encoding

- Fixed-shape events: `std.fmt.bufPrint` into stack buffer
- `agent_error`, text/thinking deltas: `allocPrint`

### 3.7 Mode wiring

- **proxy.zig:** wire `progress_fn = subagentProgressForward`, `progress_userdata = session`
- **rpc.zig:** same wiring; rpc clients already consume `tool_execution_update`
- **interactive.zig:** deferred to v3
- **print.zig:** skipped (no event bus)

## 4. Web UI integration — collapsible sub-agent panel

### 4.1 DOM structure

When `tool_execution_start` fires for `subagent` tool, extend `.tool-card` with progress panel:

```html
<div class="tool-card tool-card-subagent" data-call-id="abc">
  <div class="tool-head">
    tool: <span class="tool-name">subagent</span>
    <span class="tool-status">running…</span>
    <button class="subagent-toggle" aria-expanded="false">▶</button>
  </div>
  <div class="subagent-log" hidden>
    <div class="subagent-entry">turn 1</div>
    <div class="subagent-entry">→ bash <span class="sa-status">running</span></div>
    ...
  </div>
</div>
```

Panel starts collapsed. Toggle flips `aria-expanded` and `hidden`.

### 4.2 Detecting `subagent` tool calls

When `tool_execution_start` fires with `data.name === 'subagent'`: add class `tool-card-subagent`, append `.subagent-log` (hidden) + toggle button, create per-card `Map<cid, HTMLElement>` for tool-entry tracking.

### 4.3 Rendering `tool_execution_update`

New event handler dispatches on `upd.kind`:

| `kind` | Action |
|---|---|
| `turn_start` | Append `turn N` entry |
| `tool_start` | Append `→ <name> running`; store element in per-card `saToolEntries` map keyed by `upd.cid` |
| `tool_end` | Look up by `upd.cid`; update status to `done`/`error`; add `.is-error` class on error |
| `turn_end` | no-op |
| `error` | Append `⚠ <msg>` in error colour; auto-expand panel |
| `text_delta` | (verbose) Append/extend text entry for current block |
| `thinking_delta` | (verbose) Append/extend thinking entry for current block |

### 4.4 Toggle behaviour

- Panel starts **collapsed**
- Toggle: `▶` collapsed / `▼` expanded (styling deferred to v3)
- On parent `tool_execution_end`: update `.tool-status` to `done`/`error`; leave panel state
- **Auto-expand** when `upd.kind === 'error'` and panel collapsed

### 4.5 CSS additions (`style.css`)

`.tool-card-subagent .subagent-toggle` — no background/border, cursor pointer, muted colour. `.subagent-log` — margin/padding top, border-top, flex column. `.subagent-entry` — 11.5px, muted. Status colours: `.done` accent, `.is-error` error-border. Full visual restyle deferred to v3.
