# v2.5 design — subagent presets + SDK extensibility

**Status: decided.** All open questions resolved. Ready for implementation.
Originally v1.25; promoted to v2.5 when v2.x opened at 2.0.0 (2026-05-01).

---

## 1. Goal + non-goals

### 1.1 In scope (v2.5.0)

- `Preset` type + `PresetRegistry` for SDK-registered presets
- `subagent` tool's `parameters_json` gains dynamic `preset: enum` field from registry
- `list_subagent_presets` tool — always registered; returns structured JSON of all presets
- **Breaking change:** `preset` is now required. Implicit "inherit parent tools" removed.
- `SafetyClaims` struct on `Preset`: `max_result_bytes` enforced via existing truncation; other fields advisory
- Built-in catalog: `research`, `code-audit`, `file-ops`, `bash-runner`
- Role-promotion guard: preset's `default_role` > parent role → spawn fails with `role_promotion_denied` + hint
- SDK extensibility: consumers register custom presets before `mode.run()`; SDK preset overrides built-in of same name (warn log)

### 1.2 Out of scope (deferred to v3)

- System-prompt hint with threshold logic (≤5 hint-only, 6–15 both, 16+ tool-only)
- External-retrieval preset built-ins (k8s-read, datadog-query, etc.)
- Credential/secret handling (§3.14)
- External-tool packaging idioms (CLI shell-out, HTTP API, bundled SDK)
- `PresetContext` shape — no built-in needs ambient context beyond `parent_tools` at v2.5
- Multi-preset composition, hot-reload, versioning, per-preset config overlays, per-user ACLs
- Updated `subagent` tool description — deferred until `list_subagent_presets` ships
- Auth-token rotation in-process

## 2. Surface

### 2.1 The `Preset` type

**File:** `src/coding/tools/subagent.zig`

```zig
pub const SafetyClaims = struct {
    max_result_bytes: ?u32 = null,
    read_only: bool = false,
    requires_sandbox: bool = false,
    max_calls_per_minute: ?u32 = null,
};

pub const Preset = struct {
    name: []const u8,
    description: []const u8,
    default_profile: []const u8,
    default_role: role.Role,
    default_system_prompt: []const u8,
    build_tools: *const fn (allocator, parent_tools: []const at.AgentTool) anyerror![]at.AgentTool,
    safety: SafetyClaims = .{},
};

pub const PresetRegistry = struct {
    allocator: std.mem.Allocator,
    presets: std.StringArrayHashMapUnmanaged(Preset) = .empty,
    pub fn register(self: *@This(), p: Preset) !void { ... }
    pub fn get(self: *const @This(), name: []const u8) ?Preset { ... }
    pub fn iterator(self: *const @This()) ... { ... }
};
```

`build_tools` receives `parent_tools` (parent's filtered tool list, minus `subagent`). Full `PresetContext` deferred.

### 2.2 Built-in catalog

v2.5.0 ships workspace-local built-ins only:

| Name | Tools | Default profile | Default role |
|---|---|---|---|
| `research` | read, ls, find, grep | `gemini` | read |
| `code-audit` | read, ls, find, grep | `gemini` | read |
| `file-ops` | read, write, edit, ls | (parent's) | plan |
| `bash-runner` | bash, ls | (parent's) | code |

The v1.24 `general` preset (inherit parent tools) is **not shipped**. `preset` arg is required.

### 2.3 Discovery surface

`list_subagent_presets` tool — always registered alongside `subagent`. Returns `[{name, description, default_profile, default_role, safety}]`. Static schema (no args). System-prompt hint deferred to v3.

## 3. Resolved questions

| § | Question | Decision |
|---|---|---|
| 3.1 | One tool with `preset` arg vs one-per-preset | One tool, `preset` enum arg (N-tools bloats context) |
| 3.2 | Enum vs free-form string for `preset` | Enum generated at session-init from registry |
| 3.3 | Discovery surface | `list_subagent_presets` tool only; hint+threshold deferred to v3 |
| 3.4 | Registry scope + lifetime | Mode-driver-owned, populated at session init, frozen before use |
| 3.5 | `build_tools` ctx shape | Deferred; v2.5 passes `parent_tools` only |
| 3.6 | `general` preset back-compat | Break compat; document migration |
| 3.7 | Static vs dynamic schema | Static at session init; descriptions in list tool response |
| 3.8 | Custom tool registration model | Factory functions; tools owned by presets |
| 3.9 | Name-collision policy | SDK-registered wins, `warn` log |
| 3.10 | Preset role demotion | Parent role wins; `role_promotion_denied` + hint with required role |
| 3.11 | Test plan | 8 cases: registry, enum, dispatch, list, custom, collision, role, truncation |
| 3.12 | Naming | `Preset` |
| 3.13 | Tool description text | Deferred until `list_subagent_presets` ships |
| 3.14 | Credential/secret handling | Deferred to v3 |
| 3.15 | Guardrails (`SafetyClaims`) | Ship struct; enforce `max_result_bytes` via existing truncation |
| 3.16 | External-tool packaging idioms | Deferred to v3 |

## 5. Migration notes

| Old behaviour | v2.5 replacement |
|---|---|
| Inherits parent tools | Pick closest built-in preset |
| General delegation (all tools) | `file-ops` or `bash-runner` |
| Read-heavy analysis | `research` or `code-audit` |
| File writes | `file-ops` |
| Shell tasks | `bash-runner` |

`preset` enum field is required; omission → `invalid_args`.
