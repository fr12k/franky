# To guide the Model — Harness-Enforced Guardrails

**Status:** completed

---

## Overview

Four classes of guardrails enforced by the harness:

1. **Compilation Guard** — run build+test after N edits; inject failures as advisory hints
2. **Stuck Detector** — detect repeated same-error patterns; inject escalating hints
3. **Secret Scanner** — deferred to [v2.15 secret management](./v2.15-secret-management.md)
4. **Auto-Commit** — opt-in structured task completion with `finish_task` tool

v2.11 (model-stuck-detector) merged here; §3 is the authoritative stuck-detector spec.

## §2 — Compilation Guard

Run compilation after threshold of source-code mutations. On failure, inject structured hint as harness-synthesised tool call.

| Q | Decision |
|---|---|
| Q2.1 Where? | `between_turns` hook in `agent/loop.zig` |
| Q2.2 What counts? | `edit` + `write` invocations increment counter; `bash` does not. Resets after successful compilation |
| Q2.3 Build command? | `.franky-workflow.yaml` in workspace root: `stages` list with `name`, `command`, optional `timeout_ms`, optional `needs`. Fallback auto-detection: `build.zig`→`zig build`, `Makefile`→`make`, `Cargo.toml`→`cargo build`, else skip |
| Q2.4 Failure presentation? | Harness-synthesised tool call with `call_id = "harness:compilation_guard"`, `is_error = true`, `tool_code = "compilation_failed"`. Advisory message: "The workspace no longer compiles..." |
| Q2.5 Blocking/background? | v1 blocking with 120s timeout. Timeout → "compilation timed out", model proceeds |
| Q2.6 Threshold? | Fixed at 5 mutations for v1. Promoted to `settings.json` field `compilation_guard_threshold` later |
| Q2.7 Auto-recompile? | Re-runs after next batch crosses threshold again. No per-tool compile |
| Q2.8 False positives? | Hint is advisory; model decides urgency; further tool calls never blocked |

## §3 — Stuck Detector (merged from v2.11)

Detect when model calls same tool with similar args and gets same error repeatedly.

| Q | Decision |
|---|---|
| Q3.1 Similarity? | `tool_name` + `tool_code` + SHA-256 of canonical sorted-key JSON args. All three must match |
| Q3.2/Q3.3 Thresholds? | Hint at 5 consecutive matching errors. No hard stop in v1. Counter resets on any successful tool call |
| Q3.4 Location? | `src/agent/guardrails/stuck_detector.zig` — exposes `afterToolCall` and `betweenTurns` functions wired directly into loop hooks. `GuardrailState` aggregate in `guardrails.zig` owns a `StuckDetector` |
| Q3.5 Non-error stuck? | Deferred to v2 |

Hint message injected as harness-synthesised tool call (`call_id = "harness:stuck_detector"`): "It seems you are stuck in a loop: tool '{name}' with similar arguments has returned error '{tool_code}' {N} times..."

## §5 — Auto-Commit on Task Completion

| Q | Decision |
|---|---|
| Q5.1 How detect completion? | New `finish_task` tool (not magic text). Schema: required `commit_message` + `summary`. `terminate: true` |
| Q5.2 When commit? | After `finish_task`: run compilation (blocking). If fails → inject error, loop continues. If passes + `--auto-commit` → `git add -A && git commit -m "<message>"` |
| Q5.3 Branch strategy? | One branch per session: `franky/<session-ulid>`. Created at session start if `--auto-commit` active and on default branch |
| Q5.4 Opt-in? | Off by default. CLI `--auto-commit`, `settings.json` `auto_commit: true`, `.franky-workflow.yaml` `auto_commit: true` |
| Q5.5 Commit message? | Model-provided via `finish_task`. Harness validates: non-empty, printable ASCII |

## §6 — Event Model

**Decision:** Extend `agent_error` rather than new event kind.

Changes to `src/ai/errors.zig` / `src/agent/types.zig`:
- New `ErrorCode` enum values: `compilation_failed`, `stuck_pattern`
- New `ErrorSource` enum: `llm`, `guardrail`
- `ErrorDetails` gains `code`, `source`, `is_fatal` fields
- `AgentEvent.isTerminal()` returns true only when `is_fatal == true`
- Guardrail warnings use `is_fatal = false`, `source = .guardrail`

## §7 — Integration Architecture

```
Agent (src/agent/agent.zig)
  └── guardrails: GuardrailState

    agentLoop (src/agent/loop.zig)
      ├── after_tool_call hook:
      │   ├── stuck_detector.afterToolCall(tool, call_id, result)
      │   └── compilation_guard.bumpIfMutation(tool_name)
      ├── between_turns hook:
      │   ├── if shouldCompile(): run_build_stages() → inject harness tool result
      │   └── if stuck_detector.betweenTurns(): inject hint
      └── On finish_task:
          ├── Run compilation guard (final, blocking)
          ├── If passes + --auto-commit: git add -A && git commit
          └── Else: print summary, wait for next prompt
```

**Decision:** Guardrails directory, hybrid hook-struct pattern. Files in `src/agent/guardrails/`:

```
src/agent/guardrails/
  stuck_detector.zig       — StuckDetector struct + afterToolCall + betweenTurns
  compilation_guard.zig    — CompilationGuard struct + bumpIfMutation + runBuildStages
  finish_task.zig          — finish_task tool definition + auto-commit logic
  guardrails.zig           — GuardrailState aggregate owning all of the above
```

`GuardrailState` is a struct (not vtable). Loop's `Config` gains `guardrails: ?*GuardrailState = null`.

## §8 — Implementation Roadmap

- **Phase 1 — Stuck Detector:** `stuck_detector.zig`, wire hooks, extend ErrorDetails, tests
- **Phase 2 — Compilation Guard:** `.franky-workflow.yaml` parser, `compilation_guard.zig`, auto-detection fallback, edit counter, tests
- **Phase 3 — finish_task + Auto-Commit:** `finish_task.zig`, session-start branch creation, git integration, final compilation pass, tests
- **Phase 4 (deferred):** Secret scanner → v2.15, background compilation, hard-stop escalation, arg-hash similarity

## §9 — Configurability

| Setting | Default | Location |
|---|---|---|
| `compilation_guard_threshold` | 5 | `settings.json` |
| `compilation_guard_timeout_ms` | 120000 | `settings.json` |
| `stuck_detector_hint_threshold` | 5 | `settings.json` |
| `auto_commit` | false | `settings.json` / `.franky-workflow.yaml` / CLI `--auto-commit` |

Threshold settings in `settings.json` only. `.franky-workflow.yaml` is for workflow commands and `auto_commit` only. Hard-stop threshold reserved for v2.
