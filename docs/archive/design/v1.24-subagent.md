# v1.24 design — sub-agent tool

**Status:** shipped

Design for a `subagent` tool that lets the top-level agent spawn isolated child agents — each with its own model, provider, transcript, and tool sandbox — driven by the parent LLM via tool calls.

Decision markers: `✓ accept`, `→ override`, `?` needs discussion.

---

## 0. Why sub-agents

Single-LLM, single-context today. Sub-agents let the parent **delegate** — hand a fresh sub-agent a focused prompt, let it run to completion in its own transcript, get back the final answer. Parent's context only sees input + result, not intermediate tool calls. Net win on context-window pressure, latency (parallelism), and cost (per-task model selection).

---

## 1. Goal + non-goals

### In scope (v1.24.0)
- Built-in `subagent` tool registered in all modes.
- Args: `{profile, prompt, timeout_ms?, max_turns?, role?, system_prompt?}`.
- Inherits parent's tool set MINUS `subagent` (depth-1 only).
- Concurrent execution when LLM emits multiple `subagent` calls in same turn.
- Per-sub-agent transcript + session persistence under `<parent_session_dir>/subagents/<call_id>/`.
- Per-sub-agent timeout, max_turns, max_token spend cap.

### Out of scope (deferred)
- Multi-level recursion (hard-coded depth=1).
- Bidirectional streaming (buffered-only for v1.24; streaming follow-up v1.25).
- Inter-sub-agent communication (isolated; parent coordinates).
- Persistent sub-agents across parent turns (stateless spawn-and-die).

### What a sub-agent gets
- Full `coding/` tool layer (read/write/edit/bash/ls/find/grep) filtered by role.
- Session persistence, transcript, branching/object-store.
- Same provider + auth resolution as parent.
- Streaming events on own internal channel.
- `Cancel` flag + per-phase HTTP timeouts.

### What it does NOT get
- `subagent` tool itself (depth-1 enforcement).
- Access to parent's or sibling sub-agents' transcripts.

## 2. Surface

### 2.1 The tool

Registered alongside `read/write/edit/bash/ls/find/grep`. JSON Schema: `{profile, prompt, timeout_ms (default 1,800,000), max_turns (default 20), role, system_prompt}`.

Tool result on success: `{final_text, turn_count, tool_call_count, tokens_in, tokens_out, duration_ms, session_id}`.
Tool result on error: `{error_kind, error_message, partial_text?, turn_count, …}`.

### 2.2 Concurrent execution

Multiple `subagent` tool_use blocks in same assistant turn run in parallel via existing parallel-homogeneous execution (§4.4). Results collected in source order (deterministic transcript invariant).

### 2.3 Per-sub-agent log + transcript

```
<session_dir>/
├── transcript.json          (parent)
├── session.json
└── subagents/
    ├── <call_id_a>/
    │   ├── transcript.json
    │   ├── session.json
    │   └── meta.json        (profile, prompt, parent_call_id, started_at, ended_at, exit_kind)
    └── ...
```

## 3. Open questions & decisions

### 3.1 — LLM-driven or code-driven?
**Decision:** ✓ LLM-driven only. `subagent` is a regular tool; LLM emits `tool_use`, executor spawns sub-agent, returns result. Code-driven pipelines belong in higher-level orchestrator, not franky.

### 3.2 — Profile resolution
**Decision:** ✓ Reuse `profiles.applyProfile(...)` end-to-end. Sub-agent gets fresh `cli.Config` → `applyProfile(profile_name)` → `resolveProvider`. Same catalog precedence (project > `$FRANKY_HOME` > `$HOME` > built-in). `profile` arg only accepts profile names — NOT raw provider/model/base_url. Error: `error_kind: "profile_not_found"` with `available_profiles` list.

### 3.3 — Buffered vs. streamed result
**Decision:** ✓ Buffered for v1.24.0. Sub-agent runs to completion; tool result is final assistant message + metadata. Streaming (`subagent_event` wrapper) deferred to v1.25.0 — needs design pass on event-volume filtering.

### 3.4 — Recursion / depth limit
**Decision:** ✓ Hard-coded depth = 1. Sub-agents do NOT register `subagent` tool. Implementation: filter out subagent tool from sub-agent's tool list.

### 3.5 — Permission inheritance
**Decision:** ✓ Option C — fresh `SessionGates`, shared `Store` + `Prompter`. Always-allow/deny decisions persist across sub-agents; per-call `ask` resolutions stay per-sub-agent. Role demotion only (parent=full → sub=plan allowed; parent=plan → sub=code denied with `role_promotion_denied`).

### 3.6 — Timeout enforcement
**Decision:** → Default **30 min** (1,800,000 ms), max **2 h** (7,200,000 ms), min 1 s. Per-sub-agent timeout via existing `Cancel` mechanism + timer thread.

### 3.7 — Token / spend caps
**Decision:** → `max_turns` default **20**. Token/wall-clock cost caps deferred to v2.

### 3.8 — Failure modes + error reporting
**Decision:** ✓ Structured `error_kind` + `hint` field. Error kinds: `profile_not_found`, `role_promotion_denied`, `timeout`, `max_turns_exceeded`, `agent_error`, `aborted`, `tool_error`. Mirrors `ai/errors.zig` philosophy.

### 3.9 — Sub-agent's cwd
**Decision:** ✓ Shared with parent (same workspace). Per-path rwlock deferred to v2 if concurrent-write races emerge.

### 3.10 — Cancellation cascade
**Decision:** ✓ Cascade abort. Each in-flight sub-agent gets own `Cancel`; parent's tool executor tracks per-call cancel and fires when parent's `Cancel` fires.

### 3.11 — System prompt
**Decision:** ✓ Override-only (`system_prompt` arg). Default: franky's standard prompt MINUS subagent-tool paragraph. `append_system_prompt` deferred to v2.

### 3.12 — UI / observability
**Decision:** ✓ Print-mode stderr logs ship in v1.24.0. `subagent_status_update` event + web-UI badge deferred to v1.25.0 streaming follow-up.

### 3.13 — Naming
**Decision:** ✓ `subagent`.

## 4. Wire shape

New file: `src/coding/tools/subagent.zig`. `execute()` flow:
1. Parse args.
2. Build fresh `cli.Config` seeded with parent's `environ_map`.
3. `profiles.applyProfile(&cfg, name)`.
4. `resolveProvider` → `ProviderInfo`.
5. Build sub-Agent with parent's tools MINUS subagent.
6. Wire `SessionGates`: same Store, same Prompter, fresh role gate.
7. Allocate per-sub-agent `Cancel` + spawn timer thread.
8. Hook parent's Cancel into sub-agent's via watcher.
9. `agent.prompt(args.prompt); agent.waitForIdle();`
10. Persist transcript under `<session>/subagents/<call_id>/`.
11. Build structured `ToolResult`.

**Affected modules:** `src/coding/tools/subagent.zig` (new), `src/coding/tools/mod.zig`, `src/coding/modes/print.zig` (and proxy/rpc/interactive), `src/coding/profiles.zig`, `src/coding/role.zig`, `src/coding/session.zig`.

## 5. Tests (11 cases)

1. Happy path — faux profile, scripted text.
2. Concurrent spawn — 3 subagent calls in one turn, parallel, deterministic ordering.
3. Profile-not-found — structured error with `available_profiles`.
4. Depth-1 enforcement — sub-agent's tool list excludes `subagent`.
5. Timeout — timer fires, clean unwind, `partial_text`.
6. Cascade abort — parent cancel → child unwinds with `aborted`.
7. Role demotion — parent=full, sub=plan → tool list excludes bash/write/edit.
8. Role promotion denied — parent=plan, sub=full → `role_promotion_denied`.
9. Permission inheritance — parent's `always_allow_tools` applies to sub-agent.
10. Persistence — `subagents/<call_id>/{transcript,session,meta}.json` written.
11. System prompt — sub-agent's prompt does NOT mention `subagent` tool.

### Ship vs. slip

- **v1.24.0:** tool itself, profile-only resolution, buffered result, depth-1, shared Store/Prompter, role demotion, cascade abort, 30-min/2-h timeouts, 20-turn cap, structured errors, shared cwd, override-only system prompt, print-mode stderr. ~600-900 LOC.
- **v1.25.0:** `subagent_event` wrapper, `subagent_status_update`, web-UI badges, RPC topic.
- **v2:** multi-level recursion, persistent sub-agents, per-path rwlock, token/spend caps, append-system-prompt.
