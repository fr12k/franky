# v2.19 — Design Documents panel in the web UI

A panel inside the web UI that lists files under `docs/design/`, groups them by lifecycle state, and pre-fills the composer with a context-aware prompt.

---

## Two prompt archetypes

- **Decided doc** → implementation prompt: "Please implement the design described in `docs/design/decided/<filename>`. Read the document first, then follow the implementation plan closely. Start with the scope marked as v1 / first milestone."
- **Open doc** → design session prompt: "Let's work through the open design questions in `docs/design/open/<filename>`. Please read the document, summarise the open questions, and help me decide each one. After every question has a decision mark it with '✓ decided:' and the chosen answer inline."

Both inject only the file *path*, not full content. Agent reads with `read` tool.

## Proposed UI layout (Option A — right drawer)

```
┌─────────────────────────────────────────────┬──────────────────────┐
│  header (status, activity, …)               │                      │
├──────────────────────────────────────────────┤                      │
│ sidebar │      conversation pane            │   Design docs        │
│         │                                   │   ▼ decided (3)      │
│         │                                   │   ▼ open (1)         │
│         │                                   │   ▼ draft (2)        │
└─────────┴───────────────────────────────────┴──────────────────────┘
```

Clicking a row: fills composer with archetype prompt (if empty; toast otherwise), focuses composer, closes panel.

---

## Server-side implementation sketch

`GET /design-docs` — scan `docs/design/{,decided/,open/}`, build JSON array of `{path, name, category}`, respond 200. If directory missing → `{"docs": []}`. Read-only, stateless, no session lock.

---

## Client-side implementation sketch

Toggle button → fetch on open → render three groups → click handler dispatches on category to pre-fill composer with archetype prompt.
