# §2.4 — Richer browser UI (`franky-web-ui`)

**Status: plan (not started).** Design for the `franky-web-ui` sibling project — the richer Lit-based browser UI that v2.md §2.4 defers.

---

## 1. Rationale

The v1.5.0 in-binary MVP web UI (`src/coding/modes/web/`) is good enough for daily use and remains the default. `franky-web-ui` is a **separate sibling project** consuming the same `streamProxy` API, adding features that would bloat the in-binary MVP. Keeps the `ai → agent → coding` layering invariant intact.

**Trigger:** Independent — ships when a specific deploy needs it (PDF viewing, artifact rendering, multi-pane layouts).

---

## 2. Architecture

```
franky binary (--mode proxy)  ← SSE + REST →  franky-web-ui (Lit + TS, sibling)
  serves ./dist/ at GET /                      Served via --web-ui-root <path>
                                               or standalone Vite dev server
```

Wire format unchanged. Proxy doesn't know which UI is connected. Serving options:
1. `--web-ui-root <path>` — proxy flag overrides built-in `@embedFile` files
2. Standalone dev server — Vite proxies `/events` + REST to franky port
3. Production build — `vite build` → `./dist/` behind any static file server

---

## 3. Technology choices

| Concern | Choice | Rationale |
|---|---|---|
| Framework | **Lit** | Web Components natively; <5 kB gzipped |
| Language | **TypeScript** (strict) | Catch null/undefined at build time |
| Build tool | **Vite** | Fast DX, native TS, proxy config for dev |
| Markdown | **unified/remark** + **DOMPurify** | Modular pipeline; <15 kB gzipped |
| Syntax highlight | **Shiki** | VS Code-quality; smaller than highlight.js for full language set |
| PDF viewer | **pdfjs-dist** | Standard; lazy-loaded on first PDF (~2 MB) |
| XLSX viewer | **SheetJS** (Community Edition) | Parse to HTML tables; lazy-loaded |
| Artifact system | Custom Lit component | Expandable card with filename + size + type icon |
| Multi-pane layout | CSS Grid + Lit | Resizable via drag handle; no library |
| Editor | **ProseMirror** (via tiptap or bare) | Rich text + slash commands + @-mentions |
| State management | Lit reactive properties + URL hash | No external store |

---

## 4. Feature catalog

### 4.1 Must-have (MVP)

- Full CommonMark rendering (tables, task lists, footnotes, strikethrough, autolinks)
- Syntax-highlighted code blocks with language label, copy-button, line numbers
- Sidebar with session list, search, delete, export
- Composer: slash-command palette, multi-line, code-block toolbar, drag-and-drop upload
- Tool cards with expandable args JSON, execution time, "view full output" toggle
- Thinking blocks collapsed by default with toggle
- Responsive layout (tablet + desktop)
- SSE reconnect with `Last-Event-ID` replay

### 4.2 Nice-to-have (phase 2)

- Artifact system: PDF, XLSX, image, large-text rendered inline as expandable cards
- Multi-pane layout: left (sessions), center (chat), right (artifact preview), resizable
- Rich text composer (ProseMirror): inline formatting, slash commands, @-file references
- Dark/light theme toggle
- Conversation search via `GET /search?q=`
- Keyboard shortcuts: `Cmd+K`, `Cmd+S`, `Cmd+Shift+F`

### 4.3 Future (phase 3+)

- Offline mode (ServiceWorker, PWA manifest)
- Multi-model dashboard (live cost/token stats)
- Audio/video call (WebRTC pair session sharing)

## 7. Testing strategy

- **Unit:** Vitest for `lib/` modules
- **Component:** `@web/test-runner` or Playwright for Lit components with mock SSE
- **Integration:** Playwright against Vite dev server proxied to franky test instance
- **Fixture replay:** `franky replay <trace> --sse` emits fixture events as SSE

---

## 8. Integration with franky-core

No franky-core modifications needed. Optional `--web-ui-root <path>` flag (~20 LOC in `proxy.zig`) serves custom static files instead of embedded UI. Sibling project works standalone via Vite proxy without it.

---

## 9. Open questions

1. **Monorepo or separate repo?** → Recommendation: **separate repo** (`github.com/franky-ai/franky-web-ui`) matching sibling convention
2. **Who maintains it?** → MVP UI stays in franky-core forever. Sibling maintained by whoever deploys it
3. **Shiki vs highlight.js?** → Shiki via `vite-plugin-shiki`; fallback to highlight.js if unavailable
4. **ProseMirror + Lit maturity?** → `@prosemirror-adapter/lit` may be immature; fallback: enhanced `<textarea>` in TypeScript
