# v2.23 — coding package restructure

**Status:** ✅ Implementation complete  
**Date:** 2025-07-16  
**Implemented:** 2025-07-16 (PR)

---

## 1. Problem

`src/coding/` had 48 files, ~41K lines. `mod.zig` re-exported 38 namespaces. Symptoms: top-level namespace pollution, oversized files (session.zig 1542L, permissions.zig 1499L, profiles.zig 1332L, improvement.zig 1658L, diagnostics.zig 1608L, compaction.zig 1115L), duplicated import boilerplate across tools, no clear domain boundaries.

---

## 2. Goals

1. Reduce mod.zig re-export count from 38 to ~15-18 via subdirectories
2. Split oversized files (>800 lines) into focused sub-modules
3. Eliminate import boilerplate via centralized type aliases
4. Preserve every public API — no consumer changes beyond import paths
5. Keep `tools/` and `modes/` untouched

---

## 3. Proposed structure

```
src/coding/
  mod.zig                             # re-exports (fewer, deeper)
  tools/                              # unchanged (13 files)
  modes/                              # unchanged (4 files)
  session/                            # NEW: mod.zig, persistence.zig, compaction.zig, branching.zig, object_store.zig, replay.zig
  config/                             # NEW: cli.zig, settings.zig, profiles.zig
  security/                           # NEW: role.zig, permissions.zig, auth.zig, path_safety.zig, env_denylist.zig
  model_catalog/                      # NEW (renamed to avoid collision): catalog.zig, render.zig, fetch.zig
  extensions.zig, extensions_builtin/ # unchanged
  diagnostics.zig, improvement.zig, templates.zig  # flat
  terminal.zig, slash.zig, regex.zig, gitignore.zig, skills.zig, rpc.zig  # flat utilities
  update.zig, restart.zig             # flat operational
```

### 3.1 Rationale

| Group | Rationale |
|---|---|
| `session/` | All co-evolve around transcript persistence |
| `config/` | All answer "what configuration values are in effect?" (layered merge) |
| `security/` | All enforce access boundaries (role, permissions, auth, path/env safety) |
| `model_catalog/` | Three faces of models registry; renamed to avoid collision with `coding.models` struct |
| Flat utilities | Each standalone, imported by ≤2 consumers, small |

### 3.2 Splits

- **`session.zig`** (1542L → `session/mod.zig` 664L + `session/persistence.zig` 913L): I/O layer extracted; `Transcript` stays in `agent/loop.zig` — no `transcript.zig` created
- **`permissions.zig`** (1499L): Deferred — clean seams but needs intermediate types
- **`profiles.zig`** (1332L): Deferred — cohesive parse+apply coupling
- **`improvement.zig`** (1658L): Deferred — tightly coupled through `findings()` pipeline
- **`diagnostics.zig`** (1608L): Deferred — needs `Report` struct to split
- **`compaction.zig`** (1115L): Deferred — clean boundaries but splitting touches call sites

## 4. Redundancy elimination

### 4.1 Central type-import module (`src/coding/types.zig`)

Consolidates `ai.*` and `agent.*` imports used by 12 tool files. Each tool now writes `const ct = @import("../types.zig")` instead of copy-pasted `const ai = struct { ... }` blocks. **Savings:** ~350 lines.

### 4.2-4.5 Other patterns

- `tools/common.zig` already centralizes toolError (v1.3.0 R1) — no change
- `workspace.zig` + `path_safety.zig` + `env_denylist.zig` co-located under `security/`
- `gitignore.zig` usage pattern clean — leave as-is
- `truncate.zig` constants are single source of truth — leave as-is

## 6. Migration plan (5 phases)

1. **Create subdirs + move files** — mechanical, no content changes
2. **Create sub-module re-export files** — `session/mod.zig`, `config/mod.zig`, `security/mod.zig`, `model_catalog/mod.zig`
3. **Split `session.zig`** — extract `persistence.zig`
4. **Create `types.zig`** — update all tools/modes to use `const ct = @import("../types.zig")`
5. **Finalize `mod.zig`** — rewrite re-exports

---

## 7. Risks

| Risk | Mitigation |
|---|---|
| Import path rot | `zig build` after each phase catches every missed path |
| Behavioral change from split | Phases 1+2 are pure moves; Phase 3 re-exports same signatures |
| Merge conflicts | Single focused PR |
| `models` name collision | Use `model_catalog/` |
