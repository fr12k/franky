# v2.9 — Documentation / specification archive

**Status:** shipped — 2026-04

## Problem

Specs and design docs accumulate; old versions shouldn't pollute model's default context. `.gitignore` doesn't help — archived docs are still in git. Need parallel mechanism hiding them from default tool walks while keeping them readable on deliberate request.

## Scope: what counts as "archive"?

| Category | Examples | Archive? |
|---|---|---|
| **Frozen-but-cross-referenced spec** | `v0.md`, future `v1.md` after v2.x ships | **No** — current specs link into them |
| **Shipped design RFCs** | `v2.8-edit-tool-diff-view.md` once landed | **Yes** — implementation is source of truth |
| **RFCs that didn't ship** | abandoned proposals | **Yes** |
| **Active design RFCs** | under discussion | **No** |

Rule: RFC graduates to archive when (a) it shipped and spec/code reflects it, OR (b) discussion concluded "won't do."

## Final decision

- **Mechanism:** `.contextignore` files, parsed through existing `gitignore.zig` matcher (parameterised to load either `.gitignore` or `.contextignore` stacks).
- **Enforcement:** **Unconditional.** No tool argument, no flag, no escape hatch. Every filesystem-touching tool (`ls`, `find`, `grep`, `read`, `write`, `edit`) hard-refuses paths matched by contextignore stack. Gitignore stack remains model-controllable (`respectGitignore` flag); contextignore stack always on.
- **Naming:** `.contextignore`
- **Migration trigger:** `Status:` front-matter line on every design RFC (`draft|shipped|abandoned`). No auto-mover — convention only, manual file moves.
- **Frozen specs:** Soft-archive — file stays in place, path explicitly listed in `.contextignore`.
- **`bash` loophole:** Accepted as v1 known limitation — `bash` can still read archived paths via shell commands.

## Architecture

Matcher in `coding/gitignore.zig` parameterised so same code loads both stacks:

```
coding/gitignore.zig
  ├── loadFromTree(allocator, io, scan_root)                 (existing — defaults to ".gitignore")
  ├── loadFromTreeNamed(allocator, io, scan_root, filename)  (new — generalised)
  └── Stack.match(...)                                       (existing, filename-agnostic)

tools/{ls,find,grep,read,write,edit}.zig
  ├── load gitignore stack    if respectGitignore=true   (existing flag, model-controllable)
  ├── load contextignore stack ALWAYS                    (no flag, no override)
  └── path is excluded if either stack matches
```

No new module. No duplication of matcher. No schema changes to any tool.

## Phases

### Phase 1 — Matcher infrastructure (~80 LOC)
**File:** `src/coding/gitignore.zig` — extract filename literal from `loadFromTree` into parameter. New tests: coexistence of both stacks, empty `.contextignore`.

### Phase 2 — Tool plumbing: tree walkers (~30 LOC × 3)
**Files:** `src/coding/tools/{ls,find,grep}.zig` — add unconditional contextignore loading alongside `respectGitignore`-gated gitignore load. Path exclusion: `gitignored OR contextignored → skip`.

### Phase 3 — Tool plumbing: single-path tools (~25 LOC × 3)
**Files:** `src/coding/tools/{read,write,edit}.zig` — before IO, load contextignore stack rooted at workspace root, call `Stack.match(resolved_path)`. If matched → `tool_error{contextignored}`. Hard refusal.

### Phase 4 — Seed the repo `.contextignore`
Create `/.contextignore` with `docs/archive/` and `docs/spec/v0.md`. Plus `docs/archive/` directory (empty `.gitkeep`).

### Phase 5 — Status front-matter convention
Every file in `docs/design/` gets `Status: shipped|draft|abandoned` line at top. Convention only.

## Known limitation: `bash` loophole

`bash` runs arbitrary shell commands; can still read archived paths. V2 hardening: path-prefix sniff before exec, or chroot/namespace sandbox. V1: accept as trust-boundary limitation (not security boundary).

## Implementation order

1. `gitignore.zig` — `loadFromTreeNamed` + tests (Phase 1)
2. `ls` / `find` / `grep` — respectContextignore + tests (Phase 2)
3. `read` / `write` / `edit` — respectContextignore + tests (Phase 3)
4. Seed root `.contextignore` + `docs/archive/.gitkeep` (Phase 4)
5. `Status:` front-matter on every design RFC (Phase 5)
6. Move 2.9 design doc to `docs/design/decided/` once shipped

## Test coverage

| Layer | Test |
|---|---|
| Matcher | `loadFromTreeNamed(".contextignore")` produces identical-shape `Stack` |
| Matcher | Coexistence: tree with both files yields two independent stacks |
| `ls` | Contextignored entries hidden — no schema flag can re-enable |
| `find` | Same |
| `grep` | Same |
| `read` | Refuses contextignored path with `tool_error{contextignored}` |
| `write` | Refuses to create at contextignored path |
| `edit` | Refuses to modify contextignored file |
| Symlinks | Read through symlink whose target is contextignored → refused |
| Integration | Fixture repo — every filesystem-touching tool hides/refuses under all argument combinations |

Total: ~10 new tests. No "escape-hatch" tests (there is no escape hatch).

## Configuration

| Layer | Mechanism |
|---|---|
| Per-call | **None.** No tool argument can disable enforcement. |
| Per-session | **None for v1.** Future `--no-contextignore` CLI flag possible but not in scope. |
| Repo-level | The `.contextignore` file itself. |
